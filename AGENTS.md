# AGENTS.md - Dockhand Stacks

> Rules for AI agents creating or modifying stacks in `_stacks/`.

## Repository Context

This is a **separate git repository** (`compose-stacks.git`) from the parent
Synology ContainerManager repo (`synology-containers.git`). It contains only
Dockhand-managed application stacks.

Dockhand clones this repo and deploys stacks via its GitOps workflow. Compose
paths registered in Dockhand are relative to this repo's root (e.g.,
`homepage/compose.yaml`, not `_stacks/homepage/compose.yaml`).

## Directory Structure Per Stack

```
appname/
├── compose.yaml          # Required — Docker Compose definition
├── .env                   # Required — committed, functional defaults only
└── README.md              # Required — usage docs, env var reference, secrets list
```

**Do NOT create** any of the following files:
- `.env.example` — document variables in `README.md` instead
- `.env.secrets` / `.env.secrets.enc` / `.sops.env` — no secrets in this repo
- `docker-compose.yml` — use `compose.yaml` (Compose v2 naming)

## Secrets Policy

**No secrets are committed to this repository** — not plaintext, not SOPS/AGE
encrypted, not in any form.

- The `.env` file contains only non-secret functional defaults
- Secret values are configured by the operator via the **Dockhand API or UI**:
  - UI: Dockhand → Git Stacks → stack → Environment Variables
  - CLI: `just dockhand set-secret <stack> <key> <value>`
  - Bulk: `just dockhand load-secrets <stack> /path/to/secrets.env`
- Operators should store their secrets in a separate repository (SOPS-encrypted
  or equivalent) as their own backup/reference

### How Dockhand injects secrets

Dockhand writes secrets to `.env.dockhand` in the stack's working directory
(`/data/stacks/<name>/.env.dockhand`) at deploy time. This file is:
- Auto-generated by Dockhand, **never committed to git**
- Content is the decrypted secrets from Dockhand's encrypted SQLite DB
- Prefixed with: `# Auto-generated by Dockhand. Do not edit`

Dockhand automatically loads `.env.dockhand` alongside `.env` when running
`docker compose up`. No `env_file:` directive is needed in `compose.yaml`.

When a stack requires secrets, the `compose.yaml` references them as `${VAR}`
variables. The `README.md` must document each secret variable with:
- Variable name
- Description and purpose
- How to generate it (e.g., `openssl rand -hex 32`)
- Default credentials (if the app creates them on first start)

### Dockhand Config Sets (shared configuration)

For variables shared across multiple stacks (e.g., SMTP settings), use
**Dockhand Config Sets** instead of `config.env` or `.env`:

- Config Sets are created in the Dockhand UI (or API)
- They inject variables directly into the container environment at deploy time
- They support secrets (encrypted at rest)
- They are applied per-stack in the Dockhand UI under stack settings

**Do NOT reference Config Set variables in `compose.yaml`**. Dockhand injects
them directly -- no `${VAR}` interpolation needed. The app reads them from
its environment natively.

**SMTP Config Set example**:

Since each app uses different SMTP variable names, the Config Set includes
all variants. Each container only reads the vars it recognizes:

| Variable | Value | Used by |
|----------|-------|---------|
| `MAILER_HOST` | `smtp.example.com` | Joplin |
| `MAILER_PORT` | `587` | Joplin |
| `MAILER_AUTH_USER` | `user@example.com` | Joplin |
| `MAILER_AUTH_PASSWORD` | `***` | Joplin |
| `MAILER_NOREPLY_EMAIL` | `noreply@example.com` | Joplin |
| `SMTP_HOST` | `smtp.example.com` | Vaultwarden |
| `SMTP_PORT` | `587` | Vaultwarden |
| `SMTP_SECURITY` | `starttls` | Vaultwarden |
| `SMTP_USERNAME` | `user@example.com` | Vaultwarden |
| `SMTP_PASSWORD` | `***` | Vaultwarden |
| `SMTP_FROM` | `noreply@example.com` | Vaultwarden |

Apply the Config Set to each stack that needs email in the Dockhand UI.

## Shared Environment Variables

All stacks share a set of variables defined once in the **parent repo's**
`config.env` and propagated into each stack's `.env` via `just sync-env`.

| Variable | Example Value | Purpose |
|----------|---------------|---------|
| `LOCAL_DOMAIN` | `xyz.example.com` | Routing domain used in Traefik `Host()` rules and service URLs |
| `TZ` | `Europe/Prague` | Container timezone |
| `PUID` | `1026` | Synology user ID for file permissions |
| `PGID` | `100` | Synology group ID for file permissions |
| `DOCKER_DATA` | `/volume1/docker` | Base path for Docker data on the NAS (used by CM stacks, not Dockhand stacks) |
| `NAS_IP` | `192.168.1.100` | NAS LAN IP for DNS records |
| `DNS_IP` | `192.168.1.1` | LAN DNS server (router) for container DNS resolution |
| `TRAEFIK_NETWORK` | `traefik_proxy` | Name of the external Traefik network |

**Rules**:
- `LOCAL_DOMAIN` and `TZ` are **required** in every `.env` (validated by `just validate-env`)
- Values are overwritten by `just sync-env` — do not manually diverge from `config.env`
- Dockhand stacks typically only need `LOCAL_DOMAIN` and `TZ` (and sometimes `PUID`/`PGID`)
- `DOCKER_DATA` is used by Synology ContainerManager stacks for absolute volume paths;
  Dockhand stacks use named volumes or bind mounts to host paths instead

## The `.env` File

Committed to git. Contains **only non-secret values** with functional defaults.

### Required shared variables

Every `.env` must include at minimum (values synced from `config.env`):

```env
LOCAL_DOMAIN=xyz.example.com
TZ=Europe/Prague
```

### Stack-specific variables

Non-secret, stack-specific defaults go here too:

```env
PUID=1026
PGID=100
SIGNUPS_ALLOWED=false
```

### What does NOT go in `.env`

- Passwords, tokens, API keys, encryption keys
- Any value that would be dangerous if leaked

## The `compose.yaml` File

### Naming

Always `compose.yaml` (not `docker-compose.yml`).

### Image pinning

Pin images to specific version tags with a Renovate comment for automated updates:

```yaml
# renovate: datasource=docker depName=vendor/image
image: vendor/image:1.2.3
```

**Always verify the image name and tag exist** before committing:
- Check Docker Hub: `https://hub.docker.com/r/vendor/image/tags`
- Or: `docker pull vendor/image:1.2.3`

Use exact version tags when available. Use `latest` only when the project
does not publish versioned tags. Renovate cannot track `latest` for version
bumps (only digest changes).

### Container name

Set `container_name:` to match the stack directory name:

```yaml
container_name: appname
```

### Restart policy

```yaml
restart: unless-stopped
```

### Network

All stacks join the external `traefik_proxy` network:

```yaml
networks:
  traefik_proxy:
    external: true

services:
  appname:
    networks:
      - traefik_proxy
```

Do **not** expose ports directly (`ports:` section). All access goes through
Traefik reverse proxy.

For stacks with internal-only services (databases, Redis), add a stack-local
network:

```yaml
networks:
  traefik_proxy:
    external: true
  appname_internal:
    driver: bridge

services:
  appname:
    networks:
      - traefik_proxy
      - appname_internal
  appname-db:
    networks:
      - appname_internal
```

### Traefik labels

```yaml
labels:
  - "traefik.enable=true"
  - "traefik.http.routers.appname.rule=Host(`appname.${LOCAL_DOMAIN}`)"
  - "traefik.http.routers.appname.entrypoints=web"
  - "traefik.http.services.appname.loadbalancer.server.port=<container-port>"
```

Replace `appname` with the stack name. Replace `<container-port>` with the
port the application listens on inside the container.

For stacks that expose multiple routes (e.g., API + console), use distinct
router/service names:

```yaml
- "traefik.http.routers.appname-console.rule=Host(`appname.${LOCAL_DOMAIN}`)"
- "traefik.http.routers.appname-api.rule=Host(`api-appname.${LOCAL_DOMAIN}`)"
```

### Homepage auto-discovery labels

All stacks must include Homepage labels on the **main service** (not sidecars
like databases or Redis). Homepage reads these via Docker socket and
auto-populates the dashboard.

```yaml
labels:
  # ... Traefik labels ...
  # Homepage
  - "homepage.group=<group>"
  - "homepage.name=<Display Name>"
  - "homepage.icon=<icon-slug>"
  - "homepage.href=https://appname.${LOCAL_DOMAIN}"
  - "homepage.description=<One-line description>"
```

**Groups** (use consistently):
- `Infrastructure` -- core services (forgejo, dockhand, traefik, vaultwarden)
- `Media` -- media servers and managers (emby, navidrome, beets, calibre)
- `Applications` -- user-facing apps (joplin, paperless, excalidraw, homepage)

**Icon slugs**: use names from [Dashboard Icons](https://github.com/walkxcode/dashboard-icons).
Common: `joplin`, `emby`, `navidrome`, `paperless-ngx`, `forgejo`, `calibre`, `beets`, `excalidraw`.

Do **not** add Homepage labels to sidecar containers (databases, Redis, etc.).

### Environment variables

Reference variables from `.env` and Dockhand secrets using `${VAR}`
interpolation. Use inline defaults only for shared variables where the
fallback is obvious:

```yaml
environment:
  - TZ=${TZ:-Europe/Prague}
```

Do **not** hardcode values that should be configurable.

Secret variables are referenced the same way (`${SECRET_VAR}`) but their
values come from Dockhand at deploy time, not from `.env`.

### Volumes

Prefer named volumes for application data:

```yaml
volumes:
  appname-data:

services:
  appname:
    volumes:
      - appname-data:/data
```

Use bind mounts only when the container needs access to existing host paths
(e.g., media libraries, shared folders):

```yaml
volumes:
  - /volume1/Media/music:/music:ro
```

### Do NOT include ignore labels

Unlike Synology ContainerManager stacks, Dockhand stacks must **not** have
`dockhand.ignore` or `komodo.ignore` labels (Dockhand needs to manage them).

## The `README.md` File

Every stack directory must contain a `README.md` with the following sections.
Use `xyz.example.com` as the placeholder domain in templates; operators
substitute their actual `LOCAL_DOMAIN` value.

```markdown
# App Name

One-line description with link to upstream project.

## URL

| | URL |
|--|-----|
| **Web UI** | `https://appname.${LOCAL_DOMAIN}` |

## Deployment

Deployed via Dockhand.

### Environment Variables (`.env` defaults)

| Variable | Default | Description |
|----------|---------|-------------|
| `LOCAL_DOMAIN` | *(from config.env)* | Shared — routing domain for Traefik Host rules |
| `TZ` | `Europe/Prague` | Shared — container timezone |
| `STACK_VAR` | `value` | Stack-specific description |

### Secrets (configure in Dockhand)

| Variable | Description | Generate with |
|----------|-------------|---------------|
| `SECRET_VAR` | What it does | `openssl rand -hex 32` |

Set via: `just dockhand set-secret appname SECRET_VAR "value"`

> If no secrets are required, replace the secrets table with:
> "No secrets required."

### Default Credentials (if applicable)

| Field | Value |
|-------|-------|
| Username | `admin` |
| Password | `admin` |

> **Change immediately** after first login.

## Volumes

| Host / Volume | Container Path | Purpose |
|---------------|---------------|---------|
| `appname-data` | `/data` | Application data |

## DNS + Reverse Proxy

1. DSM reverse proxy: `appname.${LOCAL_DOMAIN}:443` -> `localhost:9980`
2. DNS: `appname.${LOCAL_DOMAIN}` -> `${NAS_IP}`
```

## Dockhand Operations

### Registering a new stack

After adding a stack directory to this repo and pushing:

```bash
just dockhand sync-all              # Pull latest from git
just dockhand add-stacks <repo-id>  # Register new stacks
just dockhand deploy appname        # Deploy
```

### Setting secrets

```bash
just dockhand set-secret appname DB_PASSWORD "$(openssl rand -base64 32)"
just dockhand load-secrets appname /path/to/secrets.env
```

### Checking stack status

```bash
just dockhand info appname          # Sync status, errors, env vars
just dockhand status                # All running stacks and containers
just dockhand list                  # All git stacks
```
